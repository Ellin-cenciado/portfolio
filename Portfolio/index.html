02 / Approach

The model
is the product.

Features change. The shape of the state shouldn't. Across these projects the same pattern keeps showing up: keep the domain rules pure, draw a hard boundary around the platform, then test the places where the two meet.

01

Pure cores

SimpleStudy's ledger and checklist logic import no GTK, D-Bus or SQLite. WebStudy reuses that same engine behind FastAPI, Electron and Chaquopy. The rules stay in one place; the shells stay disposable.

SimpleStudy · WebStudy

02

Honest boundaries

A FUSE filesystem lives or dies on memory-to-disk consistency. A Telegram bot lives or dies on a proxy timeout. I design the failure path explicitly instead of hoping the happy path holds.

big-brother-fs · TeleJob

03

Tests as documentation

Fake clocks, temporary XDG directories, synthetic FAT images, mocked syscalls and malformed-feed scenarios. The tests describe the invariants better than a paragraph ever could.

470+ tests across the set
